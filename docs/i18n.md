# i18n

`brocanth-i18n` closes the i18n part of gap G9 (Django D24). It gives
message catalogs that the build checks, locale negotiation, and CLDR plurals,
numbers and dates. Nothing ships unless the application asks for it.

## 1. Catalogs

One TOML file per locale. The file name is the BCP 47 tag.

```toml
# locales/en.toml
title = "Your cart"
greeting = "Hello, {name}!"
total = "Total: {amount:number}"
paid = "{name} paid on {day:date_long}"

[cart_items]
"=0" = "Your cart is empty"
one = "{count} item"
other = "{count} items"

[nav]
home = "Home"
```

A build script compiles the directory. The default locale is an argument, so
it is written down and not guessed.

```rust
// build.rs
fn main() {
    brocanth_i18n::build::compile("locales", "en").unwrap_or_else(|e| panic!("{e}"));
}

// src/i18n.rs
include!(concat!(env!("OUT_DIR"), "/i18n.rs"));
```

The generated file holds a `Locale` enum, with one variant per file, and a
module `t` with one function per key:

| Catalog | Call |
|---|---|
| `title = "Your cart"` | `t::title(locale)` |
| `greeting = "Hello, {name}!"` | `t::greeting(locale, name)`, any `Display` |
| `total = "Total: {amount:number}"` | `t::total(locale, 1234)`, an `i64` |
| `paid = "{name} … {day:date_long}"` | `t::paid(locale, t::Paid { name: &n, day })` |
| `[cart_items]` with `one`, `other` | `t::cart_items(locale, count)`, a `u64` |
| `[nav]` `home = "Home"` | `t::nav::home(locale)` |

Two or more arguments go in a struct with named fields, so the call site
cannot swap them. Every function returns a `String`.

`tests/golden/i18n.rs` in the crate is a complete generated file. Read it to
see what an application gets.

## 2. What fails the build

- A key that a translation has and the default locale does not.
- A placeholder that one locale has and another does not.
- A placeholder with a different type in two locales. `{day:date}` and
  `{day:date_long}` are the same type, so a translator can change the length.
- A plural with no `other`, or with a key that is not a CLDR category or `=N`.
- A key or a placeholder that cannot be a Rust name.
- A file name that is not a BCP 47 tag, and no file for the default locale.

The build reports every problem at once, with file, line and column.

The compiler checks the call sites. A misspelt key, a missing argument and an
argument of the wrong type are rustc errors. A key that no code calls is a
`dead_code` warning. Put `#[allow(dead_code)]` on the module to turn that off.

A key that a translation **lacks** is not an error. The locale falls back to
its parent (`fr-CA` to `fr`), then to the default. The build prints a
`cargo:warning` for each such key. A fallback text uses the plural rules and
number format of its own language, so an English fallback on a French page
says "0 items" and not "0 item".

## 3. Negotiation

`Negotiator` reads three sources in this order:

1. the query parameter, `?locale=fr`;
2. the cookie, `locale=fr`;
3. `Accept-Language`, highest `q` first.

Then it gives the default. It matches each value exactly, then with subtags
removed (`fr-CH` to `fr`), then by language against a regional catalog (`pt`
to `pt-BR`). A value that matches nothing is skipped. `NegotiatorConfig`
names the query parameter and the cookie; `None` turns a source off.

Two plugins, feature `plugin`:

| Plugin | Registration | What it does |
|---|---|---|
| `I18n<Locale>` | `.plugin(..)` | puts a `Negotiator<Locale>` on the context |
| `I18nHook<Locale>` | `.plugin_hooking(..)` | negotiates in a request hook; puts `Negotiated<Locale>` in the request extensions and the request state; writes `Content-Language` and `Vary` |

A handler in a generated project:

```rust
let negotiator = ctx.provided::<Negotiator<Locale>, _>().expect("dispatched");
let locale = negotiator
    .negotiate(Asked {
        query: &ctx.query,
        cookie: ctx.header("cookie"),
        accept_language: ctx.header("accept-language"),
    })
    .locale;
```

The hook keeps a `Content-Language` that the handler set. It appends to
`Vary` and does not replace it.

## 4. Templates

Neither engine needs an adapter. A key is an expression.

```rust
// an .rsx file
<h1>{t::title(locale)}</h1>
<p>{t::cart_items(locale, count)}</p>

// a jt template
"title": t::title(locale),
```

rsx escapes the text as HTML. jt writes it as a JSON string.
`tests/templates.rs` renders both.

## 5. Formatting

`Locale::formats()` gives the CLDR data for one locale. It is built once and
kept in a `static`.

| Method | `en` | `fr` |
|---|---|---|
| `plural(0)` | `Other` | `One` |
| `number(1234567)` | `1,234,567` | `1 234 567` (U+202F) |
| `fixed(1050, 2)` | `10.50` | `10,50` |
| `date(d, Long)` | `October 30, 2026` | `30 octobre 2026` |

The data is ICU4X 2.x compiled data. Dates are feature `dates`, because the
date data is the largest part.

## 6. Features and dependencies

| Feature | Adds | Dependencies |
|---|---|---|
| `runtime` (default) | `Formats`, plurals, numbers | `icu_plurals`, `icu_decimal` |
| `dates` | date formatting | `icu_datetime`, `icu_calendar` |
| `plugin` | `I18n`, `I18nHook` | `brocanth`, `http` |
| `build` | the catalog compiler | `toml`, `serde_spanned` |

The build script takes `default-features = false, features = ["build"]`.
Resolver 2 keeps build features apart from the binary's features, so the
binary links no TOML parser and the build script links no CLDR data.

## 7. Open

- No `brocanth add i18n` module yet. The scaffold is the next step.
- A generated project does not run the hook pipeline yet
  (`docs/middleware.md` §5). Until it does, use `I18n` and the context.
- Per-language URLs (`/fr/cart`, Django's `i18n_patterns`) are not built.
- The build does not check that a category exists in a locale. `few` in an
  English catalog compiles and never matches.
- No gender or other select. No ordinal plurals. No currency or time-of-day
  formatting.
- No extraction tool. The keys are the source of truth, not the strings.
