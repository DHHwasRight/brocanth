# i18n

`brocanth-i18n` closes the i18n part of gap G9 (Django D24). It gives
message catalogs that the build checks, locale negotiation, and CLDR plurals,
numbers and dates. Nothing ships unless the application asks for it.

## 1. Catalogs

One TOML file per locale. The file name is the BCP 47 tag.

```toml
# locales/en.toml
title = "Your cart"
greeting = "Hello, {name}!"
total = "Total: {amount:number}"
paid = "{name} paid on {day:date_long}"

[cart_items]
"=0" = "Your cart is empty"
one = "{count} item"
other = "{count} items"

[nav]
home = "Home"
```

A build script compiles the directory. The default locale is an argument, so
it is written down and not guessed.

```rust
// build.rs
fn main() {
    brocanth_i18n::build::compile("locales", "en").unwrap_or_else(|e| panic!("{e}"));
}

// src/i18n.rs
include!(concat!(env!("OUT_DIR"), "/i18n.rs"));
```

The generated file holds a `Locale` enum, with one variant per file, and a
module `t` with one function per key:

| Catalog | Call |
|---|---|
| `title = "Your cart"` | `t::title(locale)` |
| `greeting = "Hello, {name}!"` | `t::greeting(locale, name)`, any `Display` |
| `total = "Total: {amount:number}"` | `t::total(locale, 1234)`, an `i64` |
| `paid = "{name} … {day:date_long}"` | `t::paid(locale, t::Paid { name: &n, day })` |
| `[cart_items]` with `one`, `other` | `t::cart_items(locale, count)`, a `u64` |
| `[nav]` `home = "Home"` | `t::nav::home(locale)` |

Two or more arguments go in a struct with named fields, so the call site
cannot swap them. Every function returns a `String`.

`tests/golden/i18n.rs` in the crate is a complete generated file. Read it to
see what an application gets.

## 2. What fails the build

- A key that a translation has and the default locale does not.
- A placeholder that one locale has and another does not.
- A placeholder with a different type in two locales. `{day:date}` and
  `{day:date_long}` are the same type, so a translator can change the length.
- A plural with no `other`, or with a key that is not a CLDR category or `=N`.
- A key or a placeholder that cannot be a Rust name.
- A file name that is not a BCP 47 tag, and no file for the default locale.

The build reports every problem at once, with file, line and column.

The compiler checks the call sites. A misspelt key, a missing argument and an
argument of the wrong type are rustc errors. A key that no code calls is a
`dead_code` warning. Put `#[allow(dead_code)]` on the module to turn that off.

A key that a translation **lacks** is not an error. The locale falls back to
its parent (`fr-CA` to `fr`), then to the default. The build prints a
`cargo:warning` for each such key. A fallback text uses the plural rules and
number format of its own language, so an English fallback on a French page
says "0 items" and not "0 item".

## 3. Negotiation

`Negotiator` reads three sources in this order:

1. the query parameter, `?locale=fr`;
2. the cookie, `locale=fr`;
3. `Accept-Language`, highest `q` first.

Then it gives the default. It matches each value exactly, then with subtags
removed (`fr-CH` to `fr`), then by language against a regional catalog (`pt`
to `pt-BR`). A value that matches nothing is skipped.

`NegotiatorConfig` has five fields:

| Field | Default | What it does |
|---|---|---|
| `query` | `Some("locale")` | The query parameter. `None` turns the source off. |
| `cookie` | `Some("locale")` | The cookie. `None` turns the source off. |
| `default` | `None` | The locale when nothing matches. `None`: the catalog's default. |
| `available` | empty | The locales a request may get. Empty: every catalog. |
| `remember` | `true` | After a `?locale=` choice, the hook sets the cookie. |

**`default` is two things.** The build's default (the `build.rs` argument)
is the catalog every other one is checked against. It is fixed when the
binary is built. The `default` setting is what a request gets when it asks
for nothing offered. A French site can keep English as the complete
catalog and still answer French by default.

**`available` hides a catalog.** A catalog left out still compiles and
still backs a fallback, so a translation in progress ships without being
offered. A tag with no catalog, or a `default` that `available` leaves out,
stops the start with a `help:` line.

**`remember` makes a language switcher a link.** `?locale=fr` wins over the
cookie and the browser. The response then sets
`locale=fr; Path=/; Max-Age=31536000; SameSite=Lax; HttpOnly`, so the next
page keeps the choice without the parameter. The cookie holds a choice the
visitor made and nothing else, so it needs no consent. A cookie or an
`Accept-Language` match writes nothing: it is not a new choice.

Two plugins, feature `plugin`:

| Plugin | Registration | What it does |
|---|---|---|
| `I18n<Locale>` (`i18n-context`) | `.plugin(..)` | puts a `Negotiator<Locale>` on the context |
| `I18nHook<Locale>` (`i18n`) | `.plugin_hooking(..)` | negotiates in a request hook; puts `Negotiated<Locale>` in the request extensions, the request state and the context, and `Current` in the state; writes `Content-Language`, `Vary` and the remembered cookie |

A page in a generated project reads what the hook chose:

```rust
use crate::plugins::i18n::{self, t};

let locale = i18n::locale(ctx); // ctx.provided::<Negotiated<Locale>, _>()
let title = t::welcome(locale);
```

With `I18n` on the context instead, a handler negotiates itself:

```rust
let negotiator = ctx.provided::<Negotiator<Locale>, _>().expect("dispatched");
let locale = negotiator
    .negotiate(Asked {
        query: &ctx.query,
        cookie: ctx.header("cookie"),
        accept_language: ctx.header("accept-language"),
    })
    .locale;
```

The hook keeps a `Content-Language` that the handler set. It appends to
`Vary` and does not replace it.

### A hook reads the catalog: `Current`

A hook in a library crate cannot name the application's `Locale` type. So
the hook also writes `brocanth_i18n::Current`, the same locale with the
type erased:

```rust
if let Some(current) = state.get::<brocanth_i18n::Current>() {
    let text = current.text("gtag.banner.accept"); // Option<String>
    let tag = current.tag();                       // "fr"
}
```

`text` answers a key with no argument and no plural, by its dotted name,
with the catalog's fallback. The build script writes `Locales::message`
for it: one arm per such key. A key with an argument stays a function
only, because a lookup by name cannot check the argument. Order the hook
after `i18n.negotiate` when it is a request hook. A response hook always
runs after it.

**Reason for a lookup by name:** a library cannot call `t::key(locale)`.
The keys it reads are its contract, written in its docs. A key the
catalog lacks is `None`, and the library keeps its own text. `gtag` is the
first reader (`docs/gtag.md`).

## 4. Templates

Neither engine needs an adapter. A key is an expression.

```rust
// an .rsx file
<h1>{t::title(locale)}</h1>
<p>{t::cart_items(locale, count)}</p>

// a jt template
"title": t::title(locale),
```

rsx escapes the text as HTML. jt writes it as a JSON string.
`tests/templates.rs` renders both.

## 5. Formatting

`Locale::formats()` gives the CLDR data for one locale. It is built once and
kept in a `static`.

| Method | `en` | `fr` |
|---|---|---|
| `plural(0)` | `Other` | `One` |
| `number(1234567)` | `1,234,567` | `1 234 567` (U+202F) |
| `fixed(1050, 2)` | `10.50` | `10,50` |
| `date(d, Long)` | `October 30, 2026` | `30 octobre 2026` |

The data is ICU4X 2.x compiled data. Dates are feature `dates`, because the
date data is the largest part.

## 6. Features and dependencies

| Feature | Adds | Dependencies |
|---|---|---|
| `runtime` (default) | `Formats`, plurals, numbers | `icu_plurals`, `icu_decimal` |
| `dates` | date formatting | `icu_datetime`, `icu_calendar` |
| `plugin` | `I18n`, `I18nHook` | `brocanth`, `http` |
| `build` | the catalog compiler | `toml`, `serde_spanned` |
| `config` | `NegotiatorConfig` deserialises from `[i18n]` | `serde` |
| `scaffold` | the `i18n` module, for the CLI | `brocanth-scaffold` |

The build script takes `default-features = false, features = ["build"]`.
Resolver 2 keeps build features apart from the binary's features, so the
binary links no TOML parser and the build script links no CLDR data.

## 7. The `i18n` module

`brocanth create --with i18n` and `brocanth add i18n` write the crate into
a project. See `docs/modules/i18n.md` for the files and the settings.

| Decision | Choice | Reason |
|---|---|---|
| Catalog location | `locales/<tag>.toml` at the project root, `en` and `fr` | Beside `Cargo.toml`, where `build.rs` reads it. Two files, so negotiation has a choice on the first run. |
| Format | the TOML of §1 | No second format to learn. |
| Build wiring | the module writes `build.rs` and a `[build-dependencies]` line (`Dep::for_build`) | The crate's own path. The binary links no TOML parser, the build script no CLDR data. |
| Where the code is | `src/plugins/i18n/mod.rs`: the `include!`, `type I18n = I18nHook<Locale>`, `locale(ctx)` | The plugin directory the generator owns. A page writes `use crate::plugins::i18n::{self, t};`. |
| Plugin | `I18nHook`, registered with `configurable_hooking`, section `[i18n]` | A generated project runs the hook pipeline. The hook gives the locale to a page and to another hook. |
| How a page reads it | `i18n::locale(ctx)`, which is `ctx.provided::<Negotiated<Locale>, _>()`: the plugin moves the hook's result onto the context in `provide_for_request` | Typed, so `t::key(locale)` is checked, and the read compiles only while the plugin is registered. |
| How a hook reads it | `state.get::<Current>()`, `current.text(key)` | A library cannot name `Locale`. |
| Settings | `query`, `cookie`, `default`, `available`, `remember` | `default` and `available` are what a deployment changes. The build default stays in `build.rs`. |
| Static site | `outside_runtime` | The export runs every page through the hooks. Every exported page is in the `default` locale: an export sends no `Accept-Language`, and a file cannot vary by request. |
| Renderers | `adapts_to` `rsx` and `jt`, for `AGENTS.md` only | Neither engine needs an adapter (§4). |
| `gtag` | `i18n` `adapts_to` `gtag` and writes `[gtag.banner]` in each catalog; `gtag` `adapts_to` `i18n` and turns on its `i18n` feature | Each module writes only its own files. |
| Dead keys | `#[allow(dead_code)]` on the included module | A new project calls no key, and `clippy -D warnings` must pass. Remove the line to find unused keys. |

The generated module carries three tests: a page answers `fr` to
`Accept-Language: fr-CH`, a `?locale=fr` link wins and sets the cookie,
and each catalog has its keys with its own plural rules.

## 8. Open

- The rsx layout says `lang="en"`. A layout cannot see the request, so a
  page sets `lang` on its own root element. A slot for request values in a
  layout does not exist.
- `brocanth add i18n` after `gtag` writes the banner keys. `brocanth add
  gtag` after `i18n` cannot add them to catalogs the developer edited: copy
  the `[gtag.banner]` tables from `GTAG_EN` and `GTAG_FR` in
  `crates/brocanth-i18n/src/scaffold.rs`. The banner keeps its settings until then.
- A list setting (`available`) has no flag and no environment variable
  without `config`, as for every module.
- Per-language URLs (`/fr/cart`, Django's `i18n_patterns`) are not built.
- The build does not check that a category exists in a locale. `few` in an
  English catalog compiles and never matches.
- No gender or other select. No ordinal plurals. No currency or time-of-day
  formatting.
- No extraction tool. The keys are the source of truth, not the strings.
