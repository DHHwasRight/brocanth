# `i18n`

Translations checked at build time; a locale per request from the query, a cookie or Accept-Language.

The wizard calls it: *Show the site in more than one language*.

| | |
|---|---|
| Categories | **Middleware** |
| Wizard question | Pages |
| Default | off |
| Presets | none |
| Part of | none |
| Needs | none |
| After | none |
| Adapts to | [`config`](config.md), [`gtag`](gtag.md), [`rsx`](rsx.md), [`jt`](jt.md), [`i18n-routing`](i18n-routing.md) |
| Conflicts | none |
| Outside the runtime | yes: the static export runs the hook; every page is in the `default` locale |
| Crates | `brocanth-i18n` (twice: the runtime in `[dependencies]`, the compiler in `[build-dependencies]`) |
| Without it | one language, written into each page; nothing negotiates a locale |

## What it writes

Files:

- `build.rs`: compiles `locales/` into `$OUT_DIR/i18n.rs`. A catalog
  error stops the build with its file, line and column.
- `locales/en.toml`, the default catalog, and `locales/fr.toml`. With
  [`gtag`](gtag.md), both have a `[gtag.banner]` table.
- `src/plugins/i18n/mod.rs`: includes the generated `Locale` and `t`,
  names the plugin (`I18n`), and gives a page its locale with
  `i18n::locale(ctx)`. Its tests send `Accept-Language` and `?locale=`
  through `app::handle` and check `Content-Language` and the cookie.

Slots:

- src/plugins/mod.rs: `pub mod i18n;`
- src/plugins/mod.rs (the builder chain)
- src/plugins/mod.rs (the provider list): `i18n crate::plugins::i18n::I18n`
- src/plugins/mod.rs (the hook record): `crate::plugins::i18n::I18n`
- config/<env>.toml: `[i18n]`
- AGENTS.md: `## Translations`

The plugin is `brocanth_i18n::I18nHook<Locale>`. Its request hook puts
`Negotiated<Locale>` and `brocanth_i18n::Current` in the request state. A
page reads the first. A hook in another crate reads the second, because it
cannot name `Locale`. Its response hook writes `Content-Language`, `Vary`
and, after a `?locale=` choice, the cookie.

With [`rsx`](rsx.md) and [`jt`](jt.md), `AGENTS.md` says how a template
takes the locale. Neither engine needs an adapter: a key is an expression.

With [`i18n-routing`](i18n-routing.md), the hook reads the locale from
the path's first segment (`/fr/about`) and redirects a GET without one.
`[i18n]` gains `unprefixed`.

## Settings

Section `[i18n]`. Environment variable: `$<APP>_I18N__<KEY>`. Flag: `--i18n.<key>`. Rename or hide a flag in `src/modules/i18n.rs`.

| Key | Kind | File value | Flag | Help |
|---|---|---|---|---|
| `query` | text | `"locale"` (commented) | `--i18n.query` | The query parameter that names a locale: `?locale=fr`. Empty: not read. |
| `cookie` | text | `"locale"` (commented) | `--i18n.cookie` | The cookie that names a locale. Empty: not read. |
| `default` | text | `""` (commented) | `--i18n.default` | The locale for a request that asks for none offered. Empty: `en`, the catalog's default. A static export uses it for every page. |
| `available` | list | `[]` | none (a list) | The locales a request may get, by tag. Empty: every file in `locales/`. |
| `remember` | bool | `true` | `--i18n.remember` | A `?locale=` choice sets the cookie, so the next page keeps it. |

The default catalog, `en`, is the second argument in `build.rs`, not a
setting: the build checks every catalog against it, so it is fixed when
the binary is built. The `default` setting only chooses what a request
gets, and must be a catalog that `available` offers. A wrong tag stops
the start with a `help:` line.
