//! My Blog -- a brocanth application.
//!
//! No command line was asked for, so this binary does one thing. Everything it
//! contains is in `src/app.rs`; `brocanth create --with commands` turns this
//! into a command line with `serve` as one of its commands.

mod app;
mod pages;
mod plugins;

use std::process::ExitCode;

fn main() -> ExitCode {
    match app::serve("127.0.0.1:3000") {
        Ok(()) => ExitCode::SUCCESS,
        Err(message) => {
            eprintln!("error: {message}");
            ExitCode::FAILURE
        }
    }
}
===== src/app.rs =====
//! My Blog -- everything this binary contains, in the order it happens.
//!
//! A plugin that is not named in [`build`] is not registered, and one that is
//! not in `Cargo.toml` is not compiled at all. "The framework decided for you
//! and you cannot see where" is the thing this layout exists to make
//! impossible.
//!
//! `serve` and every other command read this, so there is one answer to what
//! this application is.

use std::sync::Arc;

use brocanth::plugin_app::AppBuilder;
use brocanth::routing::{Dispatch, MiddlewareStack, Router};
use brocanth_config::{AppBuilderConfigExt, Loader};

use crate::pages::{self, Ctx, Handler, IntoResponse, Response};
use crate::plugins;

/// The application name. Every environment variable this binary reads is
/// `MY_BLOG_<SUFFIX>`: one convention, derived once, whatever spelling the
/// name arrived in.
pub const APP: &str = "my-blog";

/// What a request needs, built once and shared by every connection.
pub struct App {
    pub router: Router<Handler>,
    pub stack: MiddlewareStack<Ctx, Response>,
    pub plugins: Vec<String>,
}

/// Builds it. The only place that decides what this binary is.
pub fn build() -> Result<App, String> {
    // 1. Configuration. The core takes already-built values; finding the
    //    files, layering them and typing each section is `brocanth-config`'s
    //    job, and it is the only reason a TOML parser is in the tree.
    //    `$MY_BLOG_ENV` picks the environment, `$MY_BLOG_CONFIG` overrides
    //    the file outright.
    let config = Loader::new(APP).load().map_err(|e| e.to_string())?;

    // 2. The application, and every plugin it contains. Each line is a line
    //    a reader can delete; nothing registers itself. A section no
    //    registered instance claims stops the build rather than being
    //    silently ignored.
    let app = AppBuilder::new()
        .with_config(config)
        .plugin_from_config::<plugins::jobs::Jobs>("jobs")
        .map_err(|e| e.to_string())?
        .setup(|setup| {
            // A plugin *offers* middleware and cannot mount it: a
            // `MiddlewareCatalog` has no `mount`. Mounting takes a pattern, the
            // pattern is a decision, and the decision is the application's.
            // Nothing in this binary offers middleware, so nothing is mounted.
            let _ = setup.router();
            Ok(())
        })
        .build()
        .map_err(|e| e.to_string())?;

    // 3. The route table: the shape of src/pages and nothing else. A file is
    //    a route, and `pages::router` is the only place that says so.
    let router = pages::router().map_err(|e| e.to_string())?;

    // 4. The chain. Nothing offered middleware, so the stack is empty --
    //    and an empty stack costs nothing: `run` allocates only when a
    //    layer matches the path.
    let stack: MiddlewareStack<Ctx, Response> = MiddlewareStack::new();

    Ok(App {
        router,
        stack,
        plugins: app.instance_names().map(str::to_string).collect(),
    })
}

/// Turns a page's answer into the bytes the server writes.
///
/// `html` rather than a guess: every page returns markup, and a handler that
/// wants another type says so with a `content-type` header, which is applied
/// after and therefore wins.
fn sent(answered: Response) -> brocanth_server::Response {
    let mut out = brocanth_server::Response::html(answered.status, answered.body);
    for (name, value) in &answered.headers {
        out = out.with_header(name, value);
    }
    out
}

/// Serves until the process is stopped.
///
/// Synchronous on the outside because the command that calls it is, and
/// the runtime is built here rather than wrapped around `main`: a command
/// that never serves should not start a reactor to run.
pub fn serve(addr: &str) -> Result<(), String> {
    let runtime = tokio::runtime::Builder::new_multi_thread()
        .enable_all()
        .build()
        .map_err(|e| e.to_string())?;

    // The runtime first, and the application inside it. A plugin
    // that opens a connection pool does it in `before_start`,
    // where the hook is synchronous and connecting is not, so it
    // reaches for the current runtime handle and blocks on a
    // scoped thread. Building the application first would leave
    // it with no handle to reach for.
    let app = {
        let _guard = runtime.enter();
        Arc::new(build()?)
    };
    eprintln!("{APP}: plugins: [{}]", app.plugins.join(", "));

    runtime.block_on(async move {
        let server = brocanth_server::Server::bind(addr)
            .await
            .map_err(|e| e.to_string())?;
        let bound = server.local_addr().map_err(|e| e.to_string())?;
        eprintln!("{APP}: listening on http://{bound}");

        server
            .run(move |request| {
                // Dispatch is synchronous and runs here, outside the
                // future, so what crosses the await is a finished
                // response and nothing borrowed.
                let out = sent(dispatch(&app, &request));
                async move { out }
            })
            .await
            .map_err(|e| e.to_string())
    })
}

/// One request: the table, then the chain, then the handler.
///
/// The chain runs only for a route that matched. A 404 has no route and
/// therefore no context, which is also why the request hooks the plan
/// reserves for a logger are the core's job and not a layer's.
pub fn dispatch(app: &App, request: &brocanth_server::Request) -> Response {
    let (verb, path) = (request.verb, request.path.as_str());
    match app.router.dispatch(verb, path) {
        Dispatch::Found { handler, matched } => {
            let mut ctx = Ctx::new(verb, path, matched.params());
            // The one place a failed handler becomes a response --
            // what Echo calls an HTTPErrorHandler. It sits inside
            // the chain's terminal, so a layer still sees what the
            // error turned into and can rewrite it.
            app.stack.run(path, &mut ctx, |c| {
                handler(c).unwrap_or_else(IntoResponse::into_response)
            })
        }
        Dispatch::MethodNotAllowed { allow, .. } => Response {
            status: 405,
            headers: vec![("allow".to_string(), allow.to_string())],
            ..Default::default()
        },
        Dispatch::NotFound => Response::new(404, "Not Found"),
    }
}
===== src/pages/mod.rs =====
//! The route table, which is this directory.
//!
//! One file is one route, and the path on disk is the URL: `index.rs` is `/`,
//! `about.rs` is `/about`, `users/[id].rs` is `/users/{id}`.
//!
//! Nothing below lists them. The macro reads this directory while the crate
//! is compiled and writes the `mod` lines and [`router`] from what is there,
//! so adding a page is adding a file and renaming one renames its route.
//! The verb comes off the handler's name: `handle` is GET, `handle_post` is
//! POST, and a `pub fn handle_*` that is not a verb is a build error rather
//! than a handler nothing reaches.
//!
//! `brocanth_pages::pages!` and `cargo expand` is how to read the result.

brocanth_pages::pages!("src/pages");

use brocanth::routing::{BuildError, Params, Router, Verb};

/// What a handler produces.
///
/// The framework owns rendering: a handler returns a value and never writes a
/// response itself, so a half-written body on an error is not something that
/// can happen. Echo and Gin hand the handler a writer and take an error back,
/// and both carry the scar -- once a 200 has gone out, the central error
/// handler cannot take it back. Here there is nothing to take back.
pub struct Response {
    pub status: u16,
    pub body: String,
    pub headers: Vec<(String, String)>,
}

/// Written by hand rather than derived, and the difference matters.
///
/// A derived `Default` would give `status: 0`, which is not an HTTP status, so
/// `Response { body: .., ..Default::default() }` would compile and be wrong.
/// 200 is what "I did not say" means for a response.
impl Default for Response {
    fn default() -> Self {
        Self {
            status: 200,
            body: String::new(),
            headers: Vec::new(),
        }
    }
}

impl Response {
    pub fn new(status: u16, body: impl Into<String>) -> Self {
        Self {
            status,
            body: body.into(),
            ..Default::default()
        }
    }

    pub fn ok(body: impl Into<String>) -> Self {
        Self::new(200, body)
    }

    pub fn empty(status: u16) -> Self {
        Self::new(status, "")
    }

    /// For what the struct literal does not cover: several headers, added one
    /// at a time. Rust has no variadic generics, so a tuple return is
    /// fixed-arity and this is the unbounded form.
    #[must_use]
    pub fn with_header(mut self, name: impl Into<String>, value: impl Into<String>) -> Self {
        self.headers.push((name.into(), value.into()));
        self
    }
}

/// What a handler may return instead of building a [`Response`] by hand.
///
/// The Crystal brocanth overloads `write_response` on the handler's return
/// type, so a page returns the simplest thing that says what it means. Rust
/// spells the same idea as a trait: each handler still returns exactly one
/// type, and this is what lets different handlers return different ones.
pub trait IntoResponse {
    fn into_response(self) -> Response;
}

impl IntoResponse for Response {
    fn into_response(self) -> Response {
        self
    }
}

/// A body, answered 200.
impl IntoResponse for String {
    fn into_response(self) -> Response {
        Response::ok(self)
    }
}

impl IntoResponse for &str {
    fn into_response(self) -> Response {
        Response::ok(self)
    }
}

/// Nothing: 200 with no body. Crystal's `Nil` return.
impl IntoResponse for () {
    fn into_response(self) -> Response {
        Response::empty(200)
    }
}

/// A status and nothing else -- `Ok(404)`.
impl IntoResponse for u16 {
    fn into_response(self) -> Response {
        Response::empty(self)
    }
}

/// A body and a status.
impl<T: IntoResponse> IntoResponse for (T, u16) {
    fn into_response(self) -> Response {
        Response {
            status: self.1,
            ..self.0.into_response()
        }
    }
}

/// A body and headers.
impl<T: IntoResponse> IntoResponse for (T, Vec<(String, String)>) {
    fn into_response(self) -> Response {
        let mut response = self.0.into_response();
        response.headers.extend(self.1);
        response
    }
}

/// A body, a status and headers.
impl<T: IntoResponse> IntoResponse for (T, u16, Vec<(String, String)>) {
    fn into_response(self) -> Response {
        let mut response = self.0.into_response();
        response.status = self.1;
        response.headers.extend(self.2);
        response
    }
}

/// What a handler may fail with.
///
/// Deliberately **not** an `impl std::error::Error`, which is what lets the
/// blanket `From` below exist without colliding with the reflexive
/// `impl<T> From<T> for T`. `anyhow::Error` is this shape for the same reason.
/// The effect is that `?` works on anything in a handler.
#[derive(Debug)]
pub struct Error {
    pub status: u16,
    pub message: String,
}

impl Error {
    pub fn new(status: u16, message: impl Into<String>) -> Self {
        Self {
            status,
            message: message.into(),
        }
    }

    /// The default for a failure nobody classified: it is a bug here, not a
    /// mistake by the caller.
    pub fn internal(message: impl Into<String>) -> Self {
        Self::new(500, message)
    }
}

impl<E: std::error::Error + Send + Sync + 'static> From<E> for Error {
    fn from(error: E) -> Self {
        Self::internal(error.to_string())
    }
}

impl IntoResponse for Error {
    fn into_response(self) -> Response {
        // Everything a client sees for a 5xx is the status. The message is for
        // whoever is reading the logs, and putting it in the body is how an
        // internal path ends up on a stranger's screen.
        let body = if self.status < 500 {
            self.message
        } else {
            String::from("Internal Server Error")
        };
        Response::new(self.status, body)
    }
}

/// What a handler is given. Middleware sees it too, and may change it before
/// the handler runs or after it returns.
pub struct Ctx {
    pub verb: Verb,
    pub path: String,
    params: Vec<(String, String)>,
}

impl Ctx {
    pub fn new(verb: Verb, path: &str, params: Params<'_>) -> Self {
        Self {
            verb,
            path: path.to_string(),
            params: params
                .iter()
                .map(|(name, value)| (name.to_string(), value.to_string()))
                .collect(),
        }
    }

    /// A route parameter, or `None`.
    ///
    /// Never `""`. The Crystal prototype returned an empty string for a name
    /// nobody declared, so a typo read as a present-but-blank value and went
    /// unnoticed; `Option` is that bug deleted rather than documented.
    pub fn param(&self, name: &str) -> Option<&str> {
        self.params
            .iter()
            .find(|(key, _)| key == name)
            .map(|(_, value)| value.as_str())
    }

    /// The same, for a parameter the route declares and so must be there.
    ///
    /// Returns `Result` rather than `Option` so it composes with `?`. A name
    /// the route does not declare is this file disagreeing with its own
    /// filename, which is a 500 and not a 400: nobody sent a bad request.
    pub fn require(&self, name: &str) -> Result<&str, Error> {
        self.param(name)
            .ok_or_else(|| Error::internal(format!("the route declares no `{name}` parameter")))
    }
}

/// A handler, as the table stores it. One per verb a page answers.
///
/// Boxed rather than a bare `fn` pointer, because every handler returns its
/// own type and a `fn` pointer can only hold one of them. [`page`] is what
/// unifies them, and it runs once per route at startup rather than per
/// request.
pub type Handler = Box<dyn Fn(&mut Ctx) -> Result<Response, Error> + Send + Sync>;

/// Puts a handler in the table whatever it returns.
///
/// Generic over the return type, so `-> Result<impl IntoResponse, Error>` on
/// the handler and one concrete `Handler` in the table are the same thing.
pub fn page<H, T>(handler: H) -> Handler
where
    H: Fn(&mut Ctx) -> Result<T, Error> + Send + Sync + 'static,
    T: IntoResponse,
{
    Box::new(move |ctx| handler(ctx).map(IntoResponse::into_response))
}

//! `/about` -- one file, one route.

use crate::pages::{Ctx, Error, IntoResponse, Response};

pub fn handle(ctx: &mut Ctx) -> Result<impl IntoResponse, Error> {
    // The context is the request. The framework owns the response, so a
    // handler returns a value and never writes one itself -- which is what
    // makes a half-written body on an error impossible rather than unlikely.
    //
    // The struct literal is the form that scales: name the fields that differ
    // and `..Default::default()` fills the rest. Rust will not let you omit a
    // field without it, and there are no implicit zero values.
    Ok(Response {
        body: format!(
            "<!doctype html><title>About \u{b7} My Blog</title>\
             <h1>About</h1>\
             <p>You asked for <code>{} {}</code>. This page answers GET and \
             nothing else, so a DELETE to it is a 405 carrying an \
             <code>Allow</code> header rather than a 404.</p>",
            ctx.verb, ctx.path
        ),
        ..Default::default()
    })
}
===== src/pages/users/[id].rs =====
//! `/users/{id}` -- the brackets in the file name are the parameter.
//!
//! There is no ceiling on how many a route may have. The Crystal prototype had
//! `MAX_PARAMS = 4` and dropped the fifth without saying so, because its
//! collector could not prove a captured parameter does not outlive the request.
//! Here the parameters borrow the path, so the question does not arise.

use crate::pages::{routes, Ctx, Error, IntoResponse, Response};

pub fn handle(ctx: &mut Ctx) -> Result<impl IntoResponse, Error> {
    // `?` is why a handler returns `Result`. Anything that fails converts
    // into `Error` through a blanket `From`, so a parse, a query or a file
    // read is one character rather than a match arm.
    let id: u64 = ctx.require("id")?.parse()?;

    Ok(Response {
        body: format!("<!doctype html><title>User {id}</title><h1>User {id}</h1>"),
        ..Default::default()
    })
}

/// POST to the same path. One file, one route, one handler per verb.
///
/// A redirect is a status, one header and no body. The struct literal above is
/// the other form; this one stays readable when there are several headers,
/// because Rust has no variadic generics and a tuple return is therefore
/// fixed-arity.
///
/// The location is built rather than written. `routes` is generated from the
/// directory alongside the table, so a link to a route that does not exist
/// does not compile, and neither does one missing a parameter.
pub fn handle_post(ctx: &mut Ctx) -> Result<impl IntoResponse, Error> {
    let id: u64 = ctx.require("id")?.parse()?;

    Ok(Response::empty(303).with_header("location", routes::users::id::path(id)))
}

===== src/plugins/jobs/mod.rs =====
//! Background jobs, as this application registers them.
//!
//! A job is a struct that serialises, plus one `perform`. Enqueuing takes the
//! struct itself, so a payload a job cannot accept is a struct-literal error
//! rather than a decode failure on a worker at three in the morning.
//!
//! `brocanth-jobs` is in `Cargo.toml` because this file is here, and through
//! no other route. Delete the registration in `src/app.rs` and delete this
//! file, and the application runs no jobs and links nothing to run them with.
//!
//! # Enqueuing
//!
//! A handler reaches the queue through the context:
//!
//! ```ignore
//! let queue: &Queue = cx.extract();
//! queue.enqueue(Welcome { user_id: 7 }).await?;
//! ```
//!
//! and a handler in an application that never registered this plugin does
//! not compile, which is the point of putting it on the context.
//!
//! # Where job types go
//!
//! `Welcome` is here so that this file compiles into something that runs.
//! Move it, and whatever follows it, into `src/jobs/` once there is more
//! than one -- the only thing that must stay here is the `register` call.
//!
//! **Register every job type before anything enqueues it.** A worker claims
//! by queue and not by name, so it will take a job whose name it does not
//! know, and a name it cannot resolve is a terminal failure: the row goes
//! straight to the dead letter rather than waiting for a worker that knows
//! it. The payload is kept and `Queue::requeue_dead` replays it, so nothing
//! is lost -- but the job does not run when you expected it to. During a
//! rolling deploy that means the old workers, so ship the registration
//! before you ship the first enqueue.
//!
//! The crate also ships `JobsPlugin`, and this is not that. `JobsPlugin` is
//! handed a queue that is already open, which is what an application with a
//! shared pool or a worker-only process wants. This one takes a URL, because
//! a new project has a URL.

use brocanth::plugin_api::{Lifecycle, Plugin, PluginError};
use brocanth::plugin_context::{ContextBuilder, ProvidesContext};
use brocanth_jobs::{Job, JobContext, JobRegistry, Queue, Worker, WorkerHandle};
use serde::{Deserialize, Serialize};

// ---------------------------------------------------------------------------
// A job
// ---------------------------------------------------------------------------

/// Says hello, slowly, somewhere that is not a request.
#[derive(Serialize, Deserialize)]
pub struct Welcome {
    /// Who to welcome.
    pub user_id: i64,
}

impl Job for Welcome {
    const NAME: &'static str = "welcome";
    /// Which queue it waits on. The worker below claims from the queues the
    /// config names, so a job on a queue nobody claims waits for ever.
    const QUEUE: &'static str = "default";
    type Error = std::io::Error;

    async fn perform(&self, _cx: &JobContext) -> Result<(), Self::Error> {
        println!("welcome, user {}", self.user_id);
        Ok(())
    }
}

/// Every job type this application can run.
///
/// The one list that has to be kept: a worker claims a row by name and needs
/// the type to decode it. Adding a job is a type above and a line here.
fn registry() -> JobRegistry {
    let mut registry = JobRegistry::new();
    registry.register::<Welcome>();
    registry
}

/// What this plugin is built from.
///
/// It derives `Deserialize` because this application reads it from
/// `[jobs]` in a TOML file. Drop the config plugin and the derive goes
/// with it: `Plugin::Config` carries no bounds the core imposes.
#[derive(Debug, serde::Deserialize)]
#[serde(default, deny_unknown_fields)]
pub struct Settings {
    /// The database the queue lives in. Its own URL, not the models': a
    /// queue and an ORM can share one database and need not.
    pub url: String,
    /// Create the three tables at startup if they are absent.
    pub migrate: bool,
    /// Run a worker in this process, as well as enqueuing from it.
    pub worker: bool,
    /// Which queues that worker claims from.
    pub queues: Vec<String>,
    /// How many jobs it runs at once.
    pub concurrency: usize,
}

impl Default for Settings {
    fn default() -> Self {
        Self {
            url: "postgres://localhost/development".to_string(),
            migrate: true,
            worker: true,
            queues: vec!["default".to_string()],
            concurrency: 5,
        }
    }
}

pub struct Jobs {
    settings: Settings,
    /// Opened at `before_start` and not before, so this is an `Option` for
    /// exactly the length of the build.
    queue: Option<Queue>,
    /// Kept so the worker can be stopped. The core's shutdown hook lands
    /// with the server layer; until then, dropping the application stops
    /// the process and the worker with it.
    worker: Option<WorkerHandle>,
}

impl Plugin for Jobs {
    type Config = Settings;
    type Provides = ProvidesContext<Queue>;
    const NAME: &'static str = "jobs";

    fn new(config: Settings) -> Self {
        Self {
            settings: config,
            queue: None,
            worker: None,
        }
    }

    fn configure(&mut self, _lc: &mut Lifecycle<'_>) -> Result<(), PluginError> {
        if self.settings.url.is_empty() {
            return Err(PluginError::new(
                "[jobs] url is required; the queue is a table and needs a database",
            ));
        }
        if self.settings.worker && self.settings.queues.is_empty() {
            return Err(PluginError::new(
                "[jobs] worker is true and queues is empty, so the worker would claim \
                 nothing; name a queue or set worker = false",
            ));
        }
        Ok(())
    }

    fn before_start(&mut self, _lc: &mut Lifecycle<'_>) -> Result<(), PluginError> {
        // The lifecycle hooks are synchronous and opening a pool is not. A
        // server process has a runtime, `block_in_place` is wrong on a
        // current-thread one, so take the handle and block the builder on a
        // scoped thread. This is startup, where blocking is expected.
        let runtime = tokio::runtime::Handle::try_current().map_err(|e| {
            PluginError::new(format!(
                "[jobs] needs a Tokio runtime at startup to open its pool ({e})"
            ))
        })?;

        let url = self.settings.url.clone();
        let migrate = self.settings.migrate;
        let queue = std::thread::scope(|scope| {
            scope
                .spawn(|| {
                    runtime.block_on(async move {
                        let queue = Queue::connect(&url).await?;
                        if migrate {
                            queue.migrate().await?;
                        }
                        Ok::<_, brocanth_jobs::Error>(queue)
                    })
                })
                .join()
                .map_err(|_| PluginError::new("the jobs connection thread panicked"))?
                .map_err(|e| PluginError::new(format!("[jobs] connecting: {e}")))
        })?;

        if self.settings.worker {
            // `enter` so that `start` finds the runtime to spawn on. The
            // worker is woken by the enqueue itself on Postgres rather than
            // polling; see `brocanth_jobs::listen`.
            let _guard = runtime.enter();
            self.worker = Some(
                Worker::builder(&queue)
                    .registry(registry())
                    .queues(self.settings.queues.clone())
                    .concurrency(self.settings.concurrency)
                    .start()
                    .map_err(|e| PluginError::new(format!("[jobs] starting the worker: {e}")))?,
            );
        }

        self.queue = Some(queue);
        Ok(())
    }

    fn provide(&self, cx: &mut ContextBuilder) {
        // `before_start` runs before the server is handed the application,
        // so the queue is here by the time any request builds a context.
        if let Some(queue) = &self.queue {
            cx.insert(queue.clone());
        }
    }
}

# Working in My Blog

A brief for a coding agent. Written by `brocanth create`, so the lists
below are this project's and not the framework's in general.

## Check your work

Run these after every change, in this order. They are ordered by how
fast they fail.

```
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

The route table is `pages::router()` and the test beside it asserts the
shape of the directory. Read it rather than guessing what covers a
request.

## What this binary contains

- `core`  the router, the context, the plugin seams
- `config`  config/<env>.toml, merged; without it nothing links a TOML parser
- `jobs`  a queue in Postgres with retries and a dead letter; a worker in this process

**Absent:** `logging`, `sessions`, `model`, `cache`, `realtime`, `commands`, `rsx`, `rsx-tailwind`, `rsx-htmx` — not compiled, not linked, absent from `Cargo.lock`. Do not write code that uses them; add the dependency and name the plugin in `main` first.

That is the framework's central rule: a capability nobody asked for is
not compiled and not linked. If you need one, add it to `Cargo.toml`
*and* name its plugin in `src/main.rs`. Nothing registers itself.

## Adding a route

A route is a file. `src/pages/about.rs` is `/about`;
`src/pages/users/[id].rs` is `/users/{id}`. **Write the file. That is
the whole of it** -- no `mod` line, no row to register, because there is
no list. `brocanth_pages::pages!` in `src/pages/mod.rs` reads this
directory while the crate compiles and writes both.

The verb comes off the handler's name: `handle` is GET, then
`handle_head`, `handle_post`, `handle_put`, `handle_patch`,
`handle_delete`, `handle_options`. A `pub fn handle_*` outside that
list is a build error naming the list, rather than a handler nothing
reaches; a page with no handler is a build error too. A private
`fn handle_*` is a helper and is left alone.

**Adding a file does not rebuild on its own** -- nothing referenced it
yet. Run `touch src/pages/mod.rs` after creating a page or a layout.
Editing or deleting one is noticed.

A handler returns a value and never writes a response itself. That is
what makes a half-written body on an error impossible rather than
unlikely.

## House style

- A comment says **why**, next to the decision, and what was chosen
  against. Not what the line does.
- A test name is a sentence describing the guarantee it protects.
- Prefer a type that cannot be built wrong over a check that can be
  forgotten.
- State a limit where someone would look for it rather than leaving it
  to be discovered.

`docs/llm-authoring.md` in the brocanth checkout is the full brief: what
